A Talos Container can wait for the machine to be ready before it starts, such as for a host path to exist or for the network to come up.
This page explains how to set those start conditions.
For more information, see the [`ContainerConfig` reference](../reference/configuration/container/containerconfig).

## Set start conditions

By default, Talos starts a container once its image is pulled and its mounts are ready.
Conditions in the `dependsOn` field make the container wait until each of them is also met.

The following conditions are available:

- **`paths`**: Host paths that must exist. Talos checks for them repeatedly and does not create them, so a path that never appears keeps the container waiting indefinitely.
- **`networks`**: Network conditions that must be ready. The conditions are `addresses`, `connectivity`, `hostname`, and `etcfiles`, which match the fields of the machine's `NetworkStatus` resource.
- **`time`**: When set to `true`, the clock must be synchronized. If time synchronization is turned off on the machine, this condition is never met.
- **`containers`**: Other Talos Containers, by name, that must start first. Talos rejects a machine configuration in which containers depend on each other in a cycle.

<Note>
Talos v1.14 accepts the `containers` condition and checks it for cycles, but does not wait for the other containers to start.
Talos v1.15 and later enforce it.
</Note>

**Example:** The following document waits for the machine's network addresses, a synchronized clock, and a file at `/var/mnt/app-config/config.yaml`:

```yaml
apiVersion: v1alpha1
kind: ContainerConfig
name: my-app
image: registry.example.com/my-app@sha256:...
dependsOn:
  paths:
    - /var/mnt/app-config/config.yaml
  networks:
    - addresses
  time: true
```

A container that waits on a condition does not appear in `talosctl containers`.
[Inspect and Troubleshoot Talos Containers](./inspect-and-troubleshoot-talos-containers#a-container-never-starts) shows how to find the condition that a container is waiting for.
