This guide sets up Calico CNI (Container Network Interface) on Talos and Omni. Calico supports two dataplane modes, [eBPF](https://docs.tigera.io/calico/latest/operations/ebpf/enabling-ebpf) and [NFTables](https://docs.tigera.io/calico/latest/getting-started/kubernetes/nftables), and you can optionally enable Calico's network [observability stack](https://docs.tigera.io/calico/latest/observability/) to inspect cluster networking and policy behavior.

## Step 1: Disable the default CNI

Talos ships with its own default CNI. Disable it before installing Calico.

<Tabs>
  <Tab title="Talos">

  Create a patch file that disables the default CNI:
  
  ```bash
  cat <<EOF > patch.yaml
  cluster:
    network:
      cni:
        name: none
  EOF
  ```

  Replace `<CLUSTER_NAME>` with a name for your cluster and `<CLUSTER_ENDPOINT>` with your control plane endpoint (for example, `https://10.5.0.2:6443`), then pass `patch.yaml` to `talosctl gen config`:
  
  ```bash
  talosctl gen config \
      <CLUSTER_NAME> <CLUSTER_ENDPOINT> \
      --config-patch @patch.yaml
  ```
  </Tab>
  <Tab title="Omni">

Add an inline patch to your cluster template:

```yaml
patches:
  - name: disable-default-cni
    inline:
      cluster:
        network:
          cni:
            name: none
```

You'll apply this patch along with the rest of the template in Step 2.

  </Tab>
</Tabs>

## Step 2: Install Calico

Calico installs via the Tigera operator. Choose the tab that matches how you manage your cluster.

<Tabs><Tab title="kubectl">

Installing via the Tigera operator manifest keeps all Calico components running and up to date. To install with Helm instead, see the [Helm installation guide](https://docs.tigera.io/calico/latest/getting-started/kubernetes/helm).

1. Set the Calico version to install:
   ```bash
   export CALICO_VERSION=v3.31.4
   ```
2. Install the Tigera operator:
   ```bash
   kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/${CALICO_VERSION}/manifests/tigera-operator.yaml
   ```
3. Configure the dataplane. See the [Installation reference](https://docs.tigera.io/calico/latest/reference/installation/api) for all available options.

<Tabs>
  <Tab title="NFTables">

```bash
kubectl create -f -<<EOF
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    bgp: Disabled
    linuxDataplane: Nftables
    ipPools:
    - name: default-ipv4-ippool
      blockSize: 26
      cidr: 10.244.0.0/16
      encapsulation: VXLAN
      natOutgoing: Enabled
      nodeSelector: all()
  kubeletVolumePluginPath: None
---
apiVersion: operator.tigera.io/v1
kind: APIServer
metadata:
  name: default
EOF
```

  </Tab>
  <Tab title="eBPF">

Calico's eBPF mode mounts cgroups from `/sys/fs/cgroup` instead of Talos's default `/var` path. Set the cgroup path first:

```bash
kubectl create -f -<<EOF
apiVersion: crd.projectcalico.org/v1
kind: FelixConfiguration
metadata:
  name: default
spec:
  cgroupV2Path: "/sys/fs/cgroup"
EOF
```

Then apply the Installation resource. Three fields matter here: set `linuxDataplane` to `BPF`, `bpfNetworkBootstrap` to `Enabled`, and `kubeProxyManagement` to `Enabled` so the operator disables kube-proxy automatically.

```bash
kubectl create -f -<<EOF
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    bgp: Disabled
    linuxDataplane: BPF
    bpfNetworkBootstrap: Enabled
    kubeProxyManagement: Enabled
    ipPools:
    - name: default-ipv4-ippool
      blockSize: 26
      cidr: 10.244.0.0/16
      encapsulation: VXLAN
      natOutgoing: Enabled
      nodeSelector: all()
  kubeletVolumePluginPath: None
EOF
```

  </Tab>
</Tabs>

  </Tab>
  <Tab title="Omni manifest sync">

Omni installs Calico by referencing manifests in a cluster template, using the [manifest sync](../../omni/cluster-management/sync-kubernetes-manifests) feature.

1. Set the Calico version to install:
   ```bash
   export CALICO_VERSION=v3.31.4
   ```
2. Download the Tigera operator manifest:
   ```bash
   curl -Lo tigera-operator.yaml https://raw.githubusercontent.com/projectcalico/calico/${CALICO_VERSION}/manifests/tigera-operator.yaml
   ```
3. Create an `installation.yaml` file with your dataplane configuration:

<Tabs>
  <Tab title="NFTables">

```yaml
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    bgp: Disabled
    linuxDataplane: Nftables
    ipPools:
    - name: default-ipv4-ippool
      blockSize: 26
      cidr: 10.244.0.0/16
      encapsulation: VXLAN
      natOutgoing: Enabled
      nodeSelector: all()
  kubeletVolumePluginPath: None
---
apiVersion: operator.tigera.io/v1
kind: APIServer
metadata:
  name: default
```

  </Tab>
  <Tab title="eBPF">

Calico's eBPF mode mounts cgroups from `/sys/fs/cgroup` instead of Talos's default `/var` path, so `installation.yaml` also needs a `FelixConfiguration` resource:

```yaml
apiVersion: crd.projectcalico.org/v1
kind: FelixConfiguration
metadata:
  name: default
spec:
  cgroupV2Path: "/sys/fs/cgroup"
---
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    bgp: Disabled
    linuxDataplane: BPF
    bpfNetworkBootstrap: Enabled
    kubeProxyManagement: Enabled
    ipPools:
    - name: default-ipv4-ippool
      blockSize: 26
      cidr: 10.244.0.0/16
      encapsulation: VXLAN
      natOutgoing: Enabled
      nodeSelector: all()
  kubeletVolumePluginPath: None
---
apiVersion: operator.tigera.io/v1
kind: APIServer
metadata:
  name: default
```

  </Tab>
</Tabs>

4. Reference both manifests in your Omni cluster template:

<CodeBlock lang="yaml">
  {`kind: Cluster\nname: my-cluster\nkubernetes:\n  version: ${k8s_release}\n  manifests:\n    - name: tigera-operator\n      file: tigera-operator.yaml\n      mode: one-time\n    - name: calico-installation\n      file: installation.yaml\n      mode: one-time\npatches:\n  - name: disable-default-cni\n    inline:\n      cluster:\n        network:\n          cni:\n            name: none\n...\n# Include machines for template`}
</CodeBlock>

5. Apply the cluster template:
   ```bash
   omnictl cluster template sync --file cluster-template.yaml
   ```

Omni waits until the Kubernetes API is available and the cluster is healthy before applying the manifests. See [Sync Kubernetes manifests](../../omni/cluster-management/sync-kubernetes-manifests) for more on manifest sync modes and status monitoring.

  </Tab>
  
</Tabs>

## Step 3: Enable network observability (optional)

Calico's Whisker stack adds a UI for observing cluster networking and policy behavior. This step works with either installation method above.

1. Deploy the Goldmane flow aggregator and the Whisker UI:

  ```bash
  kubectl create -f -<<EOF
  apiVersion: operator.tigera.io/v1
  kind: Goldmane
  metadata:
    name: default
  ---
  apiVersion: operator.tigera.io/v1
  kind: Whisker
  metadata:
    name: default
  EOF
   ```
2. Port-forward the Whisker service:

  ```bash
  kubectl port-forward -n calico-system service/whisker 8081:8081
  ```

3. Open `localhost:8081` in a browser to view policies and network flows.

## Considerations

In eBPF mode, if you can't disable kube-proxy, set `bpfKubeProxyIptablesCleanupEnabled` to `false`:

  ```bash
  kubectl patch felixconfiguration default --patch='{"spec": {"bpfKubeProxyIptablesCleanupEnabled": false}}'
  ```
